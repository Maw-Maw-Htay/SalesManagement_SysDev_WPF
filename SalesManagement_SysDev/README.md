 #\/,　 SalesManagement_SysDev プロジェクト

このディレクトリは、`SalesManagement_SysDev.sln` に含まれる現在の WPF 実装プロジェクトです。

## 利用者向け情報

起動手順、サンプルアカウント、受注登録・受注管理の操作については、ルートの [README.md](../README.md) を参照してください。

## このプロジェクトの画面

- 共通デザイン
  - ブランドはネイビー `#061A3D`、アクセントは `#2196F3`、補助色は `#90CAF9`、選択面は `#E3F2FD` です。背景 `#F8FAFC`、白いカード、本文 `#1E293B`、補助文字 `#64748B`、境界 `#E2E8F0`、入力境界 `#CBD5E1` を全画面で共有します。
  - 色、文字、再利用コントロールはそれぞれ [Resources/Colors.xaml](Resources/Colors.xaml)、[Resources/Typography.xaml](Resources/Typography.xaml)、[Resources/Controls.xaml](Resources/Controls.xaml) に定義しています。カード・フォーム・表・ダイアログの共通レイアウトは [Resources/Layouts.xaml](Resources/Layouts.xaml) を使用します。主要ボタンとサイドバーは `#061A3D`、ページ背景は `#F8FAFC`、上部ヘッダーとカードは白、選択中のナビゲーションとフォーカス表示はアクセントブルー、状態表示は成功 `#16A34A`、注意 `#D97706`、エラー `#DC2626` を使います。
  - フォントは Noto Sans JP を優先し、Yu Gothic UI、Meiryo にフォールバックします。ページタイトル24px/700、セクション見出し18px/600、カード見出し16px/600、サイドバー項目13px/500、カテゴリ12px/600、本文と入力14px/400、入力ラベル13px/500、表見出し13px/600、状態バッジ12px/500、補助・エラー文12px/400です。サイズはWPFのDPIに応じて拡大されます。
  - アイコンは公式の [Lucide](https://lucide.dev/) を同梱しています。サイドバー18px、ボタン・表操作・入力欄16px、ダッシュボードカード24px、線幅1.8px、サイドバーの文字との間隔12pxです。アイコンのみの操作ボタンは36×36px以上です。ソースとライセンスは [Resources/Lucide](Resources/Lucide/README.md) に保存しています。
  - サイドバーは展開時240px・折りたたみ時56px、メニュー行36px、上部ナビゲーションは高さ64pxです。入力欄と通常ボタンは高さ40px、ログイン入力枠は360×42px、ログインボタンは360×44pxで中央揃え、表の行と見出しは44pxです。カード角丸は8px、入力欄とボタンは6px、標準間隔は8px、節間は24px、画面余白は24pxです。
- ログイン・セッション管理
  - ログイン画面は淡いブルーの波模様を背景に中央の白いカードを配置し、システム名、社員ID、パスワード、表示切替、パスワード変更、忘れた場合の案内、ログイン操作をまとめています。画面下部にバージョン表示、カード下部に接続状態を示し、接続できない場合はログインボタンから再試行できます。再試行時は対象データベースの接続プールをリセットして接続を確認します。データベース作成・サンプルデータ登録の操作ボタンは表示しません。
  - 「パスワードを表示」で入力中のパスワードを確認できます。「パスワード変更」では社員IDと現在のパスワードを確認して新しいパスワードを設定でき、成功後はログイン欄に新しいパスワードを入力します。
  - ログイン成功後、メイン画面を使用中ディスプレイの作業領域に合わせて最大化して表示します。
  - ログイン管理では、現在のパスワード、新しいパスワード、確認用パスワードの条件を入力中に案内します。半角英数字4～10文字で、現在のパスワードと異なり、確認欄と一致した場合に変更できます。
- メインメニュー
  - ホームにはログイン中の社員名、営業所、役職と、「受注管理」「商品管理」「顧客管理」「在庫管理」へのショートカットを表示します。利用権限のある項目だけが表示され、選ぶとサイドバーの選択状態も切り替わります。
  - 幅240pxのネイビーサイドバーに「ホーム」「販売管理」「在庫・物流管理」「マスタ管理」「設定」を配置します。社員管理は管理者だけに表示し、その他の業務メニューも既存のロール・拠点権限判定に従います。メニュー間は細い区切り線で分け、メニュー領域は必要な場合だけスクロールします。
  - サイドバー左上の「販売管理システム」の左にある36×36pxの矢印で、展開（❮）と折りたたみ（❯）を切り替えます。折りたたむとシステム名・メニュー名・カテゴリ見出しを隠し、中央揃えのアイコンだけを表示します。アイコンにマウスを重ねると日本語のメニュー名を確認でき、選択中の項目は引き続き強調表示されます。状態はホーム・各管理画面・アカウント設定への移動中も保持され、メインコンテンツは残りの幅に合わせて広がります。
  - 高さ64pxの上部ナビゲーションに現在の画面名とログイン中の社員・役職・営業所を表示します。各管理画面は共通サイドバーと上部ナビゲーションを保ったまま切り替わります。サイドバー下部の「アカウント設定」からパスワード変更とログアウトを行えます。
- 社員管理
  - 管理者のみが利用できます。上部の検索欄で社員番号・社員名・ログインIDを部分検索できます。「詳細条件」で所属営業所、権限ロール、管理状態、ログイン状態、入社日範囲などを追加できます。「すべて」「表示中」「非表示」のタブに実件数を表示し、一覧は初期20件ずつ表示します。
  - ヘッダーの「社員登録」で社員番号を自動採番し、完了画面に社員番号とログインIDを表示します。初期パスワードは半角英数字4～10文字で、確認入力が必要です。パスワードは PBKDF2-SHA256 でハッシュ化して保存します。
  - 社員詳細では「基本情報」「権限情報」「変更履歴」のタブを切り替えられます。編集では保存前に変更内容を確認できます。「社員変更履歴」または詳細の「履歴管理で開く」から、共通の履歴管理で記録済みの社員登録と所属・権限変更を検索できます。
  - 「権限管理」は既存ロールの社員管理・社員変更履歴の利用範囲を表示します。機能権限の編集と他社員のパスワードリセットには対応していません。本人によるパスワード変更は引き続き利用できます。
  - アカウント無効化は理由を入力して実行します。社員フラグを `2`（非表示）に変更し、今後のログインを無効にします。社員と取引データは保持されます。自分自身と最後の有効な管理者は非表示にできず、権限変更もサービス側で認可します。
- 売上管理
  - 売上一覧は既存の `T_Sale` と `T_SaleDetail` を読み取り、売上番号・注文番号・顧客コード／名称・担当社員・営業所・売上日・金額・管理状態を表示します。管理者は全拠点、営業担当はログイン社員の所属営業所内の売上を参照できます。担当社員・営業所・期間・金額範囲・キーワードは組み合わせて自動絞り込みし、終了日は選択日の全件を含みます。
  - 集計カードは当月の表示中レコードを対象に、件数、明細に保存済みの `SaPrTotalPrice` 合計、1件あたり平均を表示します。税額・税抜額や現在の商品価格からの再計算は行いません。売上詳細の明細行も保存済み金額だけを表示します。
  - 売上の登録・更新・削除・取消は行いません。非表示は管理者のみ実行でき、理由を必須とします。既存の `SaFlag` を `0`（表示中）から `2`（非表示）へ変更し、理由を `SaHidden` に保存します。売上レコード以外の受注・出荷・在庫データは変更しません。
- 共通の管理一覧
  - 検索欄にID・名前などを入力すると、現在表示中の一覧を即時に絞り込みます。「再読込」では元データを取り直し、入力中の条件を維持します。
  - 発注・入庫・入荷・出庫・出荷・在庫・売上・注文の各一覧は、受注管理の共通リソースに基づくクイック検索、折りたたみ式の詳細条件、状態タブ、一覧カード、DataGrid を使用します。詳細は行のダブルクリックで開き、状態と管理状態は別々に表示します。
  - 状態タブは選択中に濃紺背景と白いラベル・件数・アイコンを表示し、未選択時は各画面の既存の状態色を維持します。
  - 在庫管理は有効な商品と在庫残高を対象に、登録商品数・在庫不足・在庫切れ・在庫総数を表示します。安全在庫を下回る正の在庫は「在庫不足」、0 は「在庫切れ」、安全在庫以上は「正常」です。在庫行がない商品は「未登録」として「すべて」に表示します。無効行・有効行の重複・不正な在庫数・安全在庫数の不足は「要確認」とし、詳細で理由を確認できます。売上管理は金額・件数・平均額をコンパクトに表示します。
  - 在庫一覧は初期20件で、条件変更時は1ページ目に戻ります。「CSV出力」は現在の条件に一致する全ページを UTF-8（BOM 付き）で保存します。行の「詳細」またはダブルクリックで商品・在庫情報を参照できます。在庫の最終更新日時・処理担当者・増減前後の履歴を確認できる記録がないため、日時は「未記録」と表示し、在庫推移・在庫移動履歴は利用できません。
  - 顧客、売上、注文、出庫、入荷、出荷の一覧は、管理者以外にはログイン中の社員が所属する営業所のレコードだけを表示します。営業・物流担当者も商品・顧客を参照できます。
- 受注管理（一覧、検索、確定、非表示、詳細、未確定受注の更新）
  - メインメニューの「受注管理」を選ぶと、同じメインウィンドウ内で上部ナビゲーションとサイドバーを表示したまま受注画面に切り替わります。白い上部ヘッダー左側に濃紺の「受注管理」、権限のある利用者には右側に濃紺の「受注登録」ボタンを表示し、社員・役職・営業所はスレートグレーで表示します。本文はクイック検索から始まり、大きなページ見出しを省いた一覧に、検索後の表示件数と選択件数をまとめて表示します。「詳細条件」で既存の検索項目を展開でき、フォームは初期状態で折りたたまれています。画面幅に合わせて検索項目の列数を調整し、フォーム内は必要に応じてスクロールできます。「すべて」「未確定」「確定済み」「非表示」「受注履歴」から表示を切り替えられます。サイドバーの「ホーム」で戻り、「条件クリア」は現在の画面の絞り込みを解除します。
  - 「受注履歴」は操作日時・記録IDの降順で表示し、日時、操作種別、受注番号、顧客名、短い変更要約、実行担当者、詳細操作を一覧に表示します。長い監査本文は一覧に出さず、詳細ダイアログの比較・商品別変更と折りたたみ式の記録本文で確認します。受注詳細の監査履歴表も要約を表示し、各行を選択して記録詳細を確認できます。記録済みの日時・実行者・変更前後・元の詳細は書き換えず、古い記録に存在しない値は未記録として扱います。
  - 選択した未確定受注を確定する前に件数と処理内容を確認します。確定時は既存サービスが受注確定と注文作成を行い、この段階では在庫を減算しません。確定結果・権限・入力エラーは受注画面共通のカスタムダイアログで表示します。
  - 履歴の検索欄で受注番号・顧客名・担当者・操作内容を検索し、操作種別のメニューで絞り込めます。共通の期間は履歴では操作日時（日本時間）に適用し、顧客・営業所の条件も引き継ぎます。
  - 履歴の行をダブルクリックすると、その操作時の変更内容を確認できます。受注番号を押すと現在の受注詳細を開きます。履歴は受注・顧客・担当者の更新後も操作時の情報を保持します。
  - 「条件クリア」は検索条件が1つ以上ある場合だけページ上部に表示し、「詳細条件」「受注登録」は常時表示します。詳細検索フォームは初期状態で折りたたみ、展開すると画面幅に応じて4列・3列・2列で配置します。フォーム内のスクロールバーはなく、一覧が残りの高さを使います。
  - 「条件クリア」はクイック検索、受注番号、顧客ID・顧客名、担当者、営業所、日付、納期、履歴の絞り込みを解除して自動更新します。選択中の状態タブと検索フォームの開閉状態を保持し、営業所の権限範囲は変えません。状態タブと検索条件は組み合わせて適用します。
  - 一覧のデータ列は「受注番号」「受注日 / 納期」「顧客名」「受注合計金額」「受注状態」の5項目です。画面幅に合わせて拡張・列リサイズに対応し、金額は右寄せで表示します。営業所、担当者、明細数、表示状態や明細は、行をダブルクリックして開く受注詳細で確認できます。
  - 受注詳細は900×640を基本寸法とし、モニターの作業領域とDPIに合わせて表示します。固定ヘッダーに受注番号・受注日・受付営業所を表示し、その下に状態バッジと操作ボタンを配置します。受注情報は左、顧客情報は右に表示し、確定日時・備考を含む長い値は折り返します。商品コード・商品名を分けた明細表は読み取り専用で、件数が多いときは表内をスクロールします。既存の税・端数処理を維持し、税込合計だけを太字の紺色で強調します。監査履歴は初期状態で折りたたみ、見出しに実際の件数を表示します。見出しの矢印を押すと履歴表を開閉でき、行を選択すると記録詳細を確認できます。履歴の取得中・取得失敗は件数と区別します。フッターの受付営業所・登録日・管理状態と「閉じる」は固定表示し、記録のない過去値は補完しません。確定済み受注の更新制限と、確定後のみ伝票印刷できるルールは従来どおりです。
  - 受注詳細の「伝票印刷」は受注IDで最新データを再取得し、その1件だけをA4縦のカスタムプレビューに表示します。顧客・受注情報、商品コード・商品名・単価・数量・税抜小計、税・合計、備考を表示します。印刷先は Microsoft Print to PDF を含むWindowsの印刷ダイアログで選択でき、印刷時もプレビューと同じA4縦設定を使います。確定後のみ印刷でき、印刷によるDB変更はありません。受注一覧の検索結果印刷とは独立しています。
  - 受注一覧の「印刷」は、現在の絞り込みと並び順に従って全件をA4横に表示します。長い顧客名は1行で省略表示し、全ページに見出しとページ番号を付けます。別のプリンターを選んで余白が変わった場合は、更新されたプレビューを確認してからもう一度「印刷...」を押してください。
  - 受注詳細の「非表示」ボタンは、赤い文字・アイコン・枠と白い背景で表示します。
  - 一覧の先頭列はチェックボックスだけを表示します。見出しのチェックボックスで表示中の全件を選択・解除でき、一部だけ選択すると中間状態を示します。一括操作はチェックした受注を対象とし、「選択を確定」は未確定かつ表示中、「選択を非表示」は表示中の受注がある場合だけ有効になります。非表示には理由が必要です。処理中は重複実行を防ぎ、完了後に一覧と件数を更新します。
  - 受注番号と日付欄は、それぞれ幅を確保して中央に表示します。「No.」の連番列や不要な縦の区切り線は表示しません。
  - 「受注日 / 納期」欄には、上段にカレンダーアイコンと受注日（注文日）、下段に「納期: 納品希望日」を yyyy-MM-dd 形式で表示します。見出しで受注日順に並べ替えられます。
  - 受注登録で入力した納品希望日を保存し、一覧・詳細に反映します。既存の受注で納品希望日が記録されていない場合は「納期: 未設定」と表示します。未確定・通常表示の受注は更新画面で納品希望日を編集できます。
  - 暗色の一覧コンテナに交互色の行、控えめな区切り線、選択色を適用し、チェック欄・受注番号は横スクロール中も固定表示します。省略された文字はマウスを重ねると全文を確認できます。
  - 受注の行をダブルクリックすると、その行の詳細を開きます。別の受注にチェックが付いていても、ダブルクリックした受注を表示します。
  - 詳細条件では受注番号、顧客ID・顧客名、担当者、受付営業所で絞り込めます。顧客欄は数値なら顧客ID完全一致、文字列なら顧客名の部分一致で検索し、顧客名の候補も表示します。担当者名は部分一致で検索し、候補を選ぶと担当者IDで絞り込みます。受注番号は数字または ORD-000123 形式で部分検索できます。クイック検索は受注番号・顧客ID・顧客名を含む共通検索です。受注日・納期は開始日と終了日を指定でき、「納期未設定のみ」を選ぶと納期範囲をクリアして未設定だけを表示します。
  - 検索で絞り込むと、一覧見出しの下に結果件数と適用中の条件を表示します。候補を選んだ条件はIDも表示し、長い条件はマウスを重ねると全文を確認できます。検索条件を選ぶと一覧は自動更新され、文字入力中は「条件を反映中…」と表示して短い待ち時間の後に反映されます。Ctrl+F で常時表示のクイック検索欄へ移動し、Enter で直ちに更新、Esc または欄内の × でキーワードだけ消去できます。受注番号は数字または `ORD-000123` 形式で入力できます。IDや日付の入力に誤りがある場合と結果がない場合は画面内に案内を表示します。状態タブの件数は、現在の状態タブの指定を除いた他の検索条件に対する件数です。
  - 受注状態は「未確定」「確定」を暗色に合わせた橙色・緑色のバッジで表示します。
  - 未確定かつ表示中の受注は、詳細の「受注内容を更新」から、受注登録と同じシェル・白いヘッダー・2カラムの受注更新画面を開きます。顧客は「変更」から同じ営業所の有効顧客を検索し、確認後に下書きへ反映します。顧客IDは数字、ゼロ埋め、C-付きで検索できます。受注日・納品希望日・備考・数量を編集し、商品を追加できます。受付営業所・元の受付担当者・状態は変更しません。既存明細の単価は保存済みの値、追加商品の単価は現在のマスタ値を使い、直接編集はできません。確定済み・非表示・注文連携済みの受注は更新できません。
  - 商品検索、商品詳細、＋／−付き数量入力、重複商品の数量合算、在庫表示、削除Undoは受注登録と同じ処理を使います。保存済み明細もごみ箱ボタンで受注から削除でき、既存の明細行は物理削除せず数量・金額を0にして取消状態で保持します。削除した明細は更新履歴に記録し、保存前は6秒間Undoできます。有効な明細を1件以上残して「変更を保存」すると、ヘッダー・明細・監査履歴を同じトランザクションで保存します。在庫を減算せず、新しい受注番号も作りません。在庫不明・不足だけでは保存を止めません。
  - 更新後の完了通知には実際の受注番号と「一覧に戻る」「受注詳細を表示」を表示します。×・Escは通知だけを閉じ、保存済み内容を更新画面に読み取り専用で残します。未変更の再保存を防ぎ、サイドバーとスクロールは操作できます。未保存で離れる際には破棄確認を1回だけ表示し、保存中の再送信・離脱はできません。
  - 受注は物理削除できません。表示しない場合は理由を入力して「非表示」にしてください。非表示からの復帰は管理者が理由を入力して実行し、履歴に記録します。
  - 詳細の「非表示にする」または一覧でチェックして「選択を非表示」を押すと、対象受注番号／件数を示す専用ダイアログが開きます。「非表示理由」は日本語・複数行で入力できます。空欄・空白だけでは実行できず、入力エラーは欄の直下に表示します。現行仕様に理由の文字数上限はありません。
  - 「非表示にする」を押すと「処理中…」を表示し、入力・キャンセル・×・Esc・Alt+F4・再送信を無効にします。処理前のキャンセル・×・EscではDBを変更しません。結果は同じダイアログに表示し、「閉じる」で戻ります。DBエラー時は理由を保持します。
  - 一括非表示は従来どおり受注ごとに保存する部分成功方式です。各受注で権限・営業所・現在の表示状態を再確認し、非表示と監査履歴を同じトランザクションで保存します。成功・失敗件数と失敗した受注番号を示し、「失敗分を再試行」は成功済みの受注を再送信しません。戻ると検索条件・状態タブを保持して全タブの件数を再取得し、成功分のチェックを解除、画面内に残る失敗分のチェックを保持します。「すべて」「未確定」「確定済み」は非表示を除き、「非表示」で確認できます。
  - 非表示ダイアログは標準幅460・本文に応じた高さで親の中央に開きます。親があるモニターの作業領域に対して幅95%・高さ90%以内に制限し、必要な場合だけ本文をスクロールします。
- 受注登録
  - 受注管理から受注登録ページへ移動すると、同じメインウィンドウのContentControl内で一覧を登録ページへ差し替えます。メインウィンドウ寸法と濃紺サイドバーを維持し、白い共有ヘッダーの左側にクリップボード＋アイコンと濃紺の「受注登録」、右側にログイン中の社員・役職・営業所を表示します。登録画面内に別の濃紺ヘッダーは表示しません。
  - 上部の共有ヘッダーと下部ボタンは高さ64で固定します。左側だけ必要に応じて縦にスクロールし、右側は受注一覧の中だけをスクロールして合計金額を表示したままにします。幅1000未満では日付・数量・単価を縦に並べ、低い画面では余白を縮めます。端数差の説明は合計欄にマウスを重ねても確認できます。
  - 左側で顧客コード・顧客名、営業所、商品コード・商品名・主バーコード・型番を入力して候補を絞り込みます。候補をクリックするか、下矢印で選んでEnterを押して選択してください。入力した文字だけでは有効なマスタ選択になりません。表示する営業所・顧客は従来の権限範囲を維持し、初期営業所は利用できる場合にログイン中の社員の所属営業所を選びます。
  - 受注日と納品希望日を指定し、商品と1以上の整数数量を入力して「商品を追加」を押します。数量は上下の＋／−ボタンまたは直接入力で変更でき、Enterでの確定は不要です。Enterだけで商品追加やDB登録は行いません。同じ商品は数量を合算します。追加後は商品選択を解除して数量を1へ戻し、顧客・受注情報と備考を保持します。単価と担当者は従来どおり参照専用です。単価は商品選択前に「商品選択後に表示」、選択後に商品マスタの単価を表示します。Tabでは参照専用欄を飛ばして入力・操作項目へ移動できます。
  - 右側の最上部に「受注一覧」と品目数・数量を表示し、追加した商品を即時反映します。一覧の直下に税抜合計、消費税、税込合計を表示します。行合計は税込で、ごみ箱ボタンで削除すると合計と行番号も更新されます。未追加時は左側での商品選択・追加を案内します。顧客・受注情報と備考は左側の入力欄で確認します。
  - 必須項目が未選択、日付・数量が無効、登録対象の明細がない場合は、対応する追加・登録ボタンが無効になります。未保存の入力がある状態でキャンセル・閉じる・Escを操作すると、破棄するか確認します。
  - 登録には既存のサービスとトランザクションを使用します。処理中はフッターに進捗を表示し、入力・閉じる・再送信を無効にします。失敗時は内容を保持して再試行できます。保存成功後は参考画像に合わせた完了ダイアログに緑色のチェック、完了文、実際の受注番号を表示します。×・Esc・「続けて受注登録」で閉じると、受注登録画面のまま顧客・商品・明細・備考をクリアし、数量・日付・営業所を初期値に戻して次の受注を入力できます。「受注明細を表示」は保存済み受注の詳細を開き、「一覧に戻る」は受注管理一覧を再読込します。背景フッターの主ボタンは保存中・登録成功後も「受注を登録」の表記を保ち、登録中と完了表示中は無効です。保存済み受注は保持され、登録だけでは確定・在庫引当・出荷・売上計上は行いません。
  - 現行実装上の未解決事項として、納品希望日は登録画面では必須、サービスの引数では任意です。今回の画面変更では従来の画面側の必須検証を維持しています。税率設定・価格変更権限・代替バーコードの仕組みは未実装のため、新たな業務ルールを追加せず、既存の受注詳細表示モデルの税額・丸め計算、商品マスタ単価、主バーコードを再利用します。
  - 管理者による他営業所への登録は既存の登録サービスで許可されますが、既存の確定サービスは受注担当者と営業所の所属一致を要求します。この画面では担当者をログイン社員から変更する既存ルールがないため、他営業所で登録した受注が後続の確定時に拒否される差異は未解決のままです。今回、権限・担当者割当・確定サービスは変更していません。
- 受注更新
  - 未確定・表示中・未連携の受注を、詳細の「受注内容を更新」から既存シェル内に開きます。白い共通ヘッダーとサイドバーを維持し、左に受注情報・商品入力・備考、右に明細・合計を表示します。小さい画面では各入力カード内の項目を縦に並べ、入力領域と明細だけを独立してスクロールします。フッターと合計は固定です。

  - 数量は共通の＋／−入力を使い、Enter不要で税と合計に即時反映します。無効入力中は直前の有効な合計を保持して保存を禁止します。備考は50文字以内です。保存済み明細は受注から取消でき、DB上の明細行は保持して更新履歴に記録します。新規追加分も削除・Undoできます。
  - 明細の数量欄の下に現在庫・欠品・不足数を表示します。「在庫情報が未登録です」は在庫行がない状態で、在庫0や照会失敗とは区別します。画面を操作中は約15秒ごとに表示中の商品の在庫を読み直し、数量を変更したときは不足数を即時に更新します。在庫の警告だけで未確定受注の保存を止めることはありません。
  - 「変更を保存」までDBを変更せず、保存中は入力・離脱・再送信を禁止します。未変更の保存を拒否し、失敗時は下書きを保持します。ヘッダー・明細・監査は同じトランザクションで保存し、同時編集・確定済み・非表示・連携済み受注の上書きを拒否します。在庫は減算しません。
  - 完了通知の×・Escでは更新画面に保存済み内容を読み取り専用で残します。「一覧に戻る」は一覧を再取得し、「受注詳細を表示」は保存後の受注を読み直します。通知を閉じた後もナビゲーション・スクロールを操作できます。未保存の離脱は「編集を続ける」「破棄して戻る」で1回だけ確認します。
- 受注詳細
  - タイトル・フッターの受注番号は同じ `ORD-000004` 形式で表示します。ヘッダーは68px、フッターは60pxで固定し、本文だけを縦にスクロールできます。幅900pxを基本とし、幅が狭い場合は顧客情報と受注・納期情報を縦に並べます。ウィンドウの最大高さは親ウィンドウの90%です。
  - 顧客コード、企業名、担当者、営業所、住所、電話、受注日、納品希望日、確定処理日時、受注状態、備考を、幅120pxのラベルと値の横並びで表示します。長い住所・備考は折り返し、任意の日付がない場合は「未設定」と表示します。
  - 受注状態と表示状態は別々のバッジで表示します。未確定・通常表示の受注だけ更新・確定が可能で、非表示には従来どおり権限と理由が必要です。操作は既存の業務サービスを使い、確定・非表示の完了後は従来どおり一覧が更新されます。
  - 明細は参照専用です。税抜合計、消費税合計、税込合計を分け、税込合計を強調します。消費税は従来どおり10%で、合計税額は税抜合計から四捨五入（0.5は切り上げ）します。行ごとの税額との端数差がある場合は説明を表示します。
  - 監査ログは記録済みの操作、状態・表示状態の変更、実行者、日本時間の日時、理由・詳細を新しい順で表示します。登録日・確定処理日時は実際の登録・確定ログを参照し、記録のない過去分は「未記録」と表示します。「記録開始時の状態」から過去の日時や実行者を推測しません。履歴を取得できない場合も、状態から履歴を作成せず案内を表示します。

注文管理では、常時表示の検索欄から注文番号・顧客ID・顧客名で一覧を絞り込み、テキスト入力は短い待ち時間の後に反映します。「詳細条件」では注文番号、顧客名、注文日と納期の範囲、受付営業所、注文状態、管理状態を組み合わせて指定できます。受付営業所の候補は閲覧できる注文に基づきます。開始日が終了日より後の場合はメッセージを表示し、「条件クリア」で選択中のタブを保ったまま検索条件を解除します。注文に実行担当者が一貫して記録されていないため、その項目での絞り込みはありません。

注文一覧は受注管理と同じ色を使用し、注文日と納期を同じ列に2行で表示します。未確定／確定済み／非表示の件数はログイン利用者の営業所範囲に基づき、「すべて」には非表示を含めません。仮想化した一覧は縦にスクロールでき、検索条件と一括操作は一覧の外に表示されます。選択操作は表示中の行だけを対象にします。

行の「詳細」を選ぶか行をダブルクリックすると、顧客情報・注文情報と注文明細を含む詳細ダイアログを表示します。現在庫は参考値であり、確定時に再検証します。非表示は理由（任意）を入力できる単一の確認ダイアログから実行し、キャンセルではデータを変更しません。確定・非表示は注文ごとに処理し、結果には成功・失敗件数と失敗した注文番号・理由を表示します。確定時は注文状態・在庫減算・出庫作成を同一トランザクションで保存し、重複する出庫や在庫減算を防ぎます。注文操作専用の履歴テーブルはないため追加していません。

顧客管理は顧客ID、顧客名、電話番号で自動検索できます。短い数字は顧客IDに完全一致し、例として「3」や「c-0003」で「C-0003」を検索できます。「詳細条件」で住所、担当営業所、管理状態などを組み合わせられます。状態タブは利用者の参照範囲内の件数を表示し、一覧は初期20件ずつ表示します。「すべて選択」は現在の検索結果の表示中顧客を全ページで選びます。

管理者と営業は登録・更新・非表示・復元を実行でき、営業は自営業所の顧客だけを扱います。顧客管理の利用対象は管理者と営業担当です。登録時には参照範囲内の顧客名・電話・住所に一致がある場合に確認を表示します。顧客IDは既存の DB 自動採番を使います。更新は同時編集を検出します。非表示は理由が必須です。LocalDB で確認した顧客の非表示フラグは `1` です。旧 WPF で理由付きの `2` として非表示にしたレコードも復元でき、理由のない `2` は復元対象外です。非表示・復元で受注、売上、在庫のデータは変更しません。

顧客詳細の「取引履歴（受注）」は顧客IDで紐づく受注を新しい順に表示し、詳細は参照専用で開きます。営業は顧客と受注の両方が自営業所に属する場合に参照できます。顧客マスタにはフリガナ、都道府県、担当者・営業社員、メールアドレス、取引状態、備考、登録・更新日時の項目がありません。顧客マスタの操作履歴も保存されていないため、「変更履歴」タブにはその旨を表示します。

顧客管理の検索・入力検証・ロール範囲チェックはリポジトリのルートから `dotnet run --project tests/CustomerManagementChecks -p:UseAppHost=false` で確認できます。実データの読取確認は末尾に `-- --verify-live-read` を付けます。登録・更新・非表示・復元の書込確認には `-- --verify-isolated-write` を使います。書込確認は専用の一時 DB を作成し、終了時に削除します。どちらの確認でも本番の `SalesManagement` は更新しません。

商品管理では、DB 採番の商品コード（`P-0001` 形式）、商品名、カテゴリで検索できます。「詳細条件」では管理状態、販売単価、在庫状態、メーカー、JAN、型番、発売日を組み合わせて絞り込みます。状態タブは参照できる商品の件数を表示し、一覧は初期20件ずつ表示します。

管理者と物流担当は「商品登録」と編集を利用できます。登録は既存の自動採番を使用し、在庫の初期値は従来どおり0です。販売単価を更新しても、保存済みの受注・注文・売上の明細金額や在庫数は変わりません。非表示は、未確定受注で使用中の商品には実行できません。LocalDB で非表示理由と対応している商品フラグは `1` です。過去の WPF が `2` で書き込んだ商品は、理由がある場合に限り復元できます。同じ JAN が表示中の商品に使われているときは復元できません。

商品詳細の「在庫情報」は現在庫と安全在庫を表示し、在庫残高が未登録の場合は0と区別します。「取引履歴（受注）」は商品IDで紐づいた受注明細を新しい順に表示します。単価は保存済み明細金額と数量から算出し、受注詳細は参照専用で開きます。商品管理からの受注参照は管理者が利用できます。商品マスタには仕入単価、単位、販売状態、フリガナ、説明・備考、登録・更新日時がありません。引当数、出荷可能数、在庫移動台帳、商品マスタの監査履歴も保存されていないため表示しません。

商品管理の入力・ロールチェックはリポジトリのルートから `dotnet run --project tests/ProductManagementChecks -p:UseAppHost=false` で確認できます。実データの読取確認には末尾に `-- --verify-live-read` を付けます。登録・更新・非表示・復元を試す `-- --verify-isolated-write` は専用の一時 DB を作成し、終了時に削除します。いずれも既存の `SalesManagement` を更新しません。

`PasswordBox` の入力同期、フォーカス、スクロール、ウィンドウ操作はコードビハインドで扱います。業務サービス・EFエンティティ・スキーマ初期化処理は既存のものを使用します。

受注登録は [Resources/Registration.xaml](Resources/Registration.xaml) に局所スタイル、[RegistrationLookup.xaml](Views/Shared/RegistrationLookup.xaml) に候補表示とキーボード操作を定義しています。`OrderRegistrationDataSource` は既存のマスタ取得と `BusinessService.CreateOrder` への接続だけを担当します。税額は既存の `OrderDetailViewModel` を確認用モデルとして再利用し、登録画面に税率定数を追加していません。

受注更新の検証はリポジトリ直下から `dotnet run --project tests/OrderUpdateChecks -p:UseAppHost=false` で実行できます。入力・保存状態、WPFバインディング、4解像度×3拡大率に相当する作業領域のレイアウトを検証し、`build_verify/order-update-preview` に画像を出力します。DB検証は `SalesManagement_OrderUpdateChecks_` にランダムIDを付けた専用LocalDBデータベースを作成し、保存・監査・競合・ロール・ロールバックを確認後に削除します。既存の `SalesManagement` のデータは変更しません。実ディスプレイのDPI切替を行う試験とは別です。

## 制約

売上管理では既存の出荷確定フローが作成した売上だけを扱います。売上には明細金額が保存されていますが、税額、税抜金額、登録者の履歴スナップショットは既存スキーマにないため表示・計算していません。管理フラグの非表示値 `2` はアプリ内の既存運用に合わせていますが、実LocalDBの既存値・制約はこの変更では読み取り確認していません。検証手順は [../tests/SalesManagementChecks/README.md](../tests/SalesManagementChecks/README.md) を参照してください。

社員管理は既存の `M_Employee` が保持する単一の所属営業所（`SoId`）と単一の役割（`PoId`）を使用します。ルート `SPEC.md` 4.5 の複数ロール・許可拠点の割当要件は、現行DBに割当テーブルがないため今回の対象外です。実装には社員パスワードハッシュ列と所属・権限変更履歴テーブルのみを追加しています。複数ロール・複数拠点の認可を導入する場合は、割当スキーマと全業務サービスの認可変更を別途設計してください。

受注非表示の検証手順は [../tests/OrderHideChecks/README.md](../tests/OrderHideChecks/README.md) を参照してください。入力・保存状態、キャンセル、WPFバインディング、4解像度×3拡大率の配置・レイアウトを確認し、DB検証は一意な専用DBだけで行います。

現行の非表示サービスには別途の承認フローと承認者・承認日時の項目がありません。既存監査には社員ID・操作日時・対象営業所・受注ID・理由・変更前後を記録し、承認済みと推測した情報は追加しません。承認要件を追加する場合は、仕様とスキーマの別途合意が必要です。

- 既存 SQL Server LocalDB `SalesManagement` と EF Core エンティティを使用します。
  - 起動時に受注テーブルへ nullable の納品希望日（OrDeliveryDate）列を追加します。既存の受注日・明細・金額は保持します。
- 受注の非表示は管理フラグを `2` にする方式です。
- 初回起動時に操作履歴用の `T_OrderOperationHistory` テーブルを追加します。既存の業務テーブルは再作成しません。履歴と業務データは同じトランザクションで保存します。
- 履歴記録開始前の受注は「記録開始時の状態」として一度だけ記録します。過去の操作日時・実行者・変更前の値は推測せず、未記録として扱います。
- 取引データは物理削除しません。
- 実行中のアプリが出力ファイルをロックしている場合、ビルド前にアプリを終了してください。

### 発注管理

- 管理者と物流担当は、既存の `T_Hattyu` / `T_HattyuDetail` を使って1件の発注に複数商品を登録できます。発注番号はDB採番、発注担当者はログイン中の社員を使用し、登録時はヘッダーと全明細を同一トランザクションで保存します。
- 一覧は発注番号・仕入先・商品コード・商品名・担当者、発注期間、入庫状況で絞り込めます。初期表示は20件ずつで、CSVは絞り込み結果の全ページを出力します。商品マスタとの関係は `M_Product.MaId` を使用し、仕入先と一致する有効商品だけを登録できます。登録完了後は採番された発注の詳細を開けます。
- 入庫済数量は `T_Warehousing` の有効かつ棚入れ確定済み（`WaFlag = 0`、`WaShelfFlag = 1`）の明細を発注・商品ごとに合算します。すべての商品数量が一致すると「入庫済」となります。未入庫数量は商品ごとの不足分を合算し、過剰入庫を区別します。発注詳細・発注履歴の「関連入庫」から既存の入庫記録を参照できます。発注の操作監査イベントは未記録です。
- 在庫パネルは有効な `T_Stock.StQuantity`、商品マスタの `PrSafetyStock`、既存発注の棚入れ確定数量から求めた未入庫発注数量を参照し、補充点と重複発注の確認を促します。標準発注量の列はありません。登録・非表示は在庫数量、入庫ヘッダー、入庫明細を変更しません。
- 選択した発注の「発注書出力」または詳細の「発注書印刷」からA4縦の印刷プレビューを開けます。発注書は実際の仕入先・担当者・商品・数量を使います。営業所は担当者の現在の所属を表示します。仕入単価、発注金額、納品予定日、備考、発注時の営業所、発注元会社名は既存スキーマに記録されていません。独立した発注確定と発注の編集には業務ルールと記録先の合意が必要です。
- 管理者・物流担当は一覧と登録を利用でき、非表示データの閲覧と理由必須の非表示は管理者だけに許可します。非表示は `HaFlag = 2` と `HaHidden` を更新する論理操作で、発注・入庫の関係は保持します。
- 非表示の判定には既存の `HaFlag = 2` を使います。現在のLocalDBで `HaFlag` の値と発注・入庫の関連を読み取り確認しています。
- 検証手順は [../tests/PurchaseOrderChecks/README.md](../tests/PurchaseOrderChecks/README.md) を参照してください。これらのチェックはデータベースを更新しません。実 `SalesManagement` LocalDB 上での登録・入庫連携は、この変更では統合実行していません。

### 入荷管理

- 入荷一覧は既存の `T_Arrival` / `T_ArrivalDetail` を使い、キーワード・入荷日・営業所・担当者・入荷状態で絞り込みます。管理者は全営業所と非表示分を確認でき、営業担当者は自営業所の表示中データだけを扱います。物流担当者はこの画面を利用できません。
- 入荷確定は営業担当者または管理者に許可し、サービス層で利用者の有効状態・役割・営業所を再検証します。確定済み状態への遷移と未確定の出荷情報作成を、入荷行ロックを含む直列化可能トランザクションで保存します。再試行・同時確定では既存の状態を検出して出荷を重複作成しません。
- 確定時は同じ注文・顧客・営業所に属する確定済み出庫を照合し、商品ごとの数量合計が入荷明細と一致する候補が1件だけの場合に進みます。候補なし・複数候補・数量差異は拒否します。出荷情報には注文・顧客・営業所・商品・数量を引き継ぎ、出荷状態は未確定で保存します。注文・顧客・営業所単位の既存出荷も確認し、重複作成を拒否します。出荷確定、在庫残高、入庫記録はこの処理では変更しません。
- 非表示は管理者のみ実行でき、入荷確定済みであることと理由の入力を必須にします。理由は500文字以内で `ArHidden` に保存します。未確定入荷は非表示にできず、非表示処理は入荷・注文・出荷・在庫を削除・変更しません。
- 既存 `T_Arrival` に出庫番号や出荷ID、`T_Shipment` に入荷IDがないため、既存の注文・顧客・営業所キーと出庫明細数量から一意に照合します。入荷との直接外部キーや1対1対応は記録できず、同一注文に複数入荷がある場合に出荷を入荷単位で追跡できるとは扱いません。スキーマ変更は行っていません。
- 既存の入荷明細数量を出荷明細へ引き継ぎます。予定数量と実入荷数量を分ける列はないため差異管理はできず、入荷数量は明細に記録済みの値を使います。
- 入荷管理の検索・状態遷移・明細検証・ロール・非表示理由は `dotnet run --project tests/ArrivalManagementChecks -p:UseAppHost=false` で確認できます。これらはデータベースを更新しません。実 LocalDB 上の入荷確定・出荷作成・並行実行・非表示保存は別途統合確認が必要です。

### 出荷管理

- 出荷管理は既存 `T_Shipment` / `T_ShipmentDetail` を使い、出荷番号・注文番号・顧客・営業所・商品・数量・確定状態を一覧と読み取り専用詳細に表示します。入荷番号は出荷テーブルに保存されていないため表示せず、確定時に注文・顧客・営業所と商品数量が一致する確定済み入荷を一意に照合します。
- キーワード、確定日、出荷状況をAND条件で部分一致検索し、すべて／表示中／非表示を切り替えます。確定日が未設定の未確定出荷は日付範囲指定時に対象外です。条件クリアは管理タブを維持します。集計カードは表示中・全期間のDBレコードから計算します。
- 出荷確定は管理者・営業担当者に許可し、サービス層で社員状態・役割・営業所を再確認します。出荷行をロックする直列化可能トランザクション内で、関連注文、商品数量、確定済み入荷と売上を再検証してから状態・確定日・担当者を更新します。在庫、入荷、出荷明細を再作成・更新しません。
- 既存の出荷確定から売上を登録するアプリ内連携は保持します。注文ごとの売上範囲をロックして既存売上がないときだけ1件登録し、既存売上がある場合は顧客・営業所・商品数量を照合して再利用します。複数売上、関係不一致、数量差異、複数の同一キー出荷、入荷の欠落・曖昧一致は確定を拒否します。二重確定や再試行は状態ロックとサービス検証で止めます。
- 非表示は管理者と自営業所の出荷を扱う営業担当者が実行でき、確定済みであることと500文字以内の理由入力をサービス側で再確認します。`ShFlag = 2` と `ShHidden` を保存する論理操作で、出荷・入荷・注文・売上・在庫は削除・変更しません。500文字は既存の入荷管理に合わせたアプリ側上限で、今回の実LocalDBスキーマの列長は接続できず確認できていません。
- 出荷・入荷間に直接外部キーがないため、現行DBでは一意の入荷参照番号を恒久的に保持できません。確定時の照合は既存列と明細数量だけを使い、複数候補を推測で選びません。スキーマ変更はしていません。
- 検索、日付範囲、状態遷移、数量照合、売上再利用・重複ガード、ロール、非表示理由は `dotnet run --project tests/ShipmentManagementChecks -p:UseAppHost=false` で確認できます。これらのチェックはDBを更新しません。実 `SalesManagement` LocalDB は検証環境から接続できなかったため、列長、並行確定、ロールバック、WPF実行時表示は統合確認が必要です。

### 入庫管理・出庫管理

- 管理者・物流担当は入庫／出庫一覧、部分一致検索、複合条件、期間、詳細を利用できます。管理者だけが非表示記録を参照できます。確定・非表示では現在の社員・役割・拠点を再検証し、非表示には理由が必要です。未確定記録は非表示にできず、物理削除は行いません。
- 入庫一覧は1つのクイック検索、折りたたみ式の詳細条件、実件数の状態タブ、初期20件のページ表示を備えます。「すべて」は表示中の入庫です。選択した未確定の入庫1件を確認ダイアログから確定できます。詳細条件の入庫日は保存済みの `WaDate`、発注日は参照権限のある発注の `HaDate` を使用します。
- 「入庫履歴」は確定済みの業務記録を入庫日の新しい順に表示します。管理者は非表示の確定済み記録も参照できます。入庫詳細から、実際の発注IDで関連発注を参照専用で開けます。「在庫情報」は現在庫と安全在庫の参照専用です。
- 管理者は理由が記録された確定済みの非表示入庫を復元できます。復元は `WaFlag` だけを変更し、確定状態、数量、発注ID、非表示理由を保持します。非表示理由のない旧記録や未確定の非表示記録は復元しません。発注画面の入庫済数量は従来どおり表示中の確定済み入庫を集計するため、復元した記録はその集計対象に戻ります。出庫の復元は提供しません。
- 出庫管理一覧はキーワード検索、折りたたみ可能な詳細条件、出庫状態タブ、件数カード、初期20件のページ表示を備えます。「すべて」は表示中の出庫、管理者の「非表示」は非表示の出庫を表示します。「入荷未完了」は関連する入荷が未確定の出庫の件数です。出庫履歴は確定済みの業務記録を表示し、出庫の操作履歴は「未記録」と表示します。
- 出庫詳細では商品・数量を参照できます。関連注文は注文・顧客・営業所と商品数量が一致する確定済み注文が1件の場合に表示し、関連入荷も同じキーと数量で一意に照合します。閲覧権限のある場合は、関連注文と入荷の詳細を参照専用で開けます。
- 入庫の棚入れ確定は、発注との商品関係・有効商品・正の数量を検証し、入庫状態と `T_Stock.StQuantity` を直列化可能トランザクション内で一度だけ更新します。在庫行が完全に存在しない場合は既存 `BusinessService.EnsureStock` を使用し、欠損・重複する有効在庫行は安全のため拒否します。発注数量超過は既存の発注管理で表示する仕様に合わせ、棚入れ自体は数量差異を記録したうえで確定可能です。入庫担当者と入庫日は保持します。専用の確定者・確定日時列はないため、確定者を上書き保存しません。
- 出庫確定は、確定済み注文と出庫明細の全商品数量が一意に一致することを検証し、出庫状態更新と未確定の入荷ヘッダー・明細作成を一つのトランザクションで保存します。注文確定時の在庫減算を繰り返さず、入荷確定・出荷作成も行いません。注文・顧客・営業所の組み合わせに既存入荷がある場合は重複防止のため拒否します。
- 現行スキーマには倉庫別在庫列、棚入れ確定日時・確定担当者列、入荷から出庫への直接ID列がありません。そのため現在庫は商品単位、入庫日は既存 `WaDate` とし、入庫担当者は保持します。出庫は既存社員列に確定担当者を保存します。出庫と入荷は注文・顧客・営業所の組み合わせで重複確認し、直接の外部キーは追加していません。倉庫単位の在庫移動や出庫IDの永続リンクが必要な場合は、スキーマ変更を別途合意してください。
- 入庫の数量修正や手動登録には既存の操作フローがありません。入庫予定日、入庫時の担当営業所、単位、引当数、出荷可能数、在庫移動台帳、入庫操作履歴は現行スキーマに保存されていません。発注担当者の営業所を表示する場合は現在の所属として表示します。
- `dotnet run --project tests/WarehouseMovementChecks -p:UseAppHost=false` に `-- --receiving-ui` を付けると入庫UI、`-- --receiving-read` で実データの読み取り、`-- --receiving-isolated` で確定・競合・非表示・復元の検証ができます。書き込み試験は専用の一時DBだけを使います。

### 受注登録の数量・在庫表示

受注登録・受注更新・在庫管理は `T_Stock` の商品IDと同じ在庫判定を使用します。残高として表示できるのは、有効な行が1件あり数量が0以上の場合です。受注では入力した数量に対して不足を判定し、在庫管理では商品マスタの安全在庫を基準にします。「在庫情報が未登録です」と表示されたときは、在庫担当者が入庫記録と現物を確認してください。実際の未確定入庫が記録されている場合は、入庫管理で照合して棚入れを確定します。既存在庫の残高だけが欠落している場合は、照合した数量を承認済みの初期残高として登録する手続きが必要です。

商品入力と明細の数量は、直接入力と＋／−ボタンで変更でき、Enterでの確定は不要です。行金額・税・合計は即時に更新します。商品選択時に `T_Stock` の商品単位在庫を再取得し、在庫数・欠品・不足・確認できない状態を数量欄の近くに表示します。在庫行なし、無効行、複数の有効行、照会失敗は別の状態として扱い、在庫情報だけを理由に受注登録を止めません。受注登録では在庫を減算しません。明細削除後は6秒間「元に戻す」で復元できます。商品・在庫テーブルに商品単位の設定列がないため、現在の数量単位表示は既存の在庫表示と同じ「個」です。登録成功後は完了ダイアログに緑色のチェック、完了文、実際の受注番号と「続けて受注登録」「受注明細を表示」「一覧に戻る」を表示します。×・Esc・「続けて受注登録」で入力を初期状態に戻し、同じ受注登録画面で次の受注を開始できます。背景の「受注を登録」ボタンは完了表示中に無効となり、登録中と完了ダイアログ表示中の二重登録を防止します。

### 履歴管理

サイドバーの「履歴管理」は共通画面内に開きます。キーワードを入力すると少し待って自動検索します。「詳細条件」で操作種別・対象番号・対象名・操作日（日本時間）・担当者を組み合わせられます。「処理結果」は記録されていないため条件にできません。業務区分タブで切り替え、20件または50件ずつ表示します。ある業務に監査の保存先がない場合は、件数の代わりに未記録と案内します。

「詳細」では記録済みの変更前後と、受注の場合は実際に比較できる商品明細を確認できます。明細金額から計算した単価には計算方法を表示し、現在の単価や商品コードで過去の値を補いません。受注の「記録開始時の状態」は比較用のスナップショットです。行を選択して「タイムライン」を開くと、その対象の記録だけを古い順に確認できます。

| 業務 | 操作・変更履歴 | 業務履歴・既存の参照先 |
| --- | --- | --- |
| 受注 | 保存済み監査と記録開始時の状態。営業は所属営業所、管理者は全営業所 | 既存の受注履歴・詳細内の履歴、業務履歴の確定済み受注 |
| 注文 | 未記録 | 注文履歴から確定済み注文 |
| 発注 | 未記録 | 既存の発注履歴の入庫実績、業務履歴の入庫完了済み発注 |
| 入庫・出庫 | 未記録 | 既存の入庫履歴・出庫履歴から確定済み記録 |
| 入荷・出荷 | 未記録 | 各履歴から確定済み記録 |
| 売上 | 未記録 | 売上履歴から売上伝票 |
| 在庫 | 未記録。在庫移動台帳もなし | 現在庫と既存の入出庫実績。増減前後の残高・日時・担当者は推測しない |
| 顧客・商品 | 未記録 | 詳細の「変更履歴」で未記録と案内。既存の受注取引履歴は別表示 |
| 社員 | 管理者のみ。登録・所属／権限変更を記録。氏名・連絡先・非表示の監査は未実装 | 社員詳細の変更履歴、および中央履歴への社員指定リンク |

「業務履歴」は保存済みの完了取引を読み取り専用で開きます。伝票日は保存済みの日付で、処理を行った日時とは限りません。閲覧権限は各サービスで確認します。履歴表示は在庫、業務状態、監査行を更新しません。監査の対象を追加する場合は、対象操作・保存項目・権限・既存の確定トランザクションとの境界を合意してから実装します。

履歴画面、権限別フィルター、既存受注履歴のベースライン表示をDB接続なしで確認するには、`dotnet run --project ../tests/HistoryManagementChecks -p:UseAppHost=false` を実行してください。チェック項目は [../tests/HistoryManagementChecks/README.md](../tests/HistoryManagementChecks/README.md) に記載しています。

サイドバーでは「履歴管理」を「システム管理」セクションに置き、他の管理メニューと同じ行形式で表示します。履歴通知バッジは、ログイン中に保存に成功した受注更新および社員の所属/権限変更の監査記録を数え、中央の履歴管理が正常に読み込まれると0に戻します。0件では隠し、100件以上は「99+」で表示します。ログアウト時にも0へ戻し、再起動後や他ユーザーによる更新は含みません。利用者ごとの既読状態・未読件数の永続化は未実装で、監査履歴がない他モジュールの更新は数えません。DBスキーマや永続保存処理は追加していません。
